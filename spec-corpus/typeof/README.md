# Independent mapping-time type constraints

`generated-cases.json` defines grammars, typed evaluator consumer methods, and
handwritten input/value/failure/CP-span expectations. `invalid-cases.json` fixes
pre-generation diagnostic codes. `probe.rs.txt` only observes generated APIs; it
does not derive or rewrite expected values.

Each of the 32 grammars is generated by Java and native Rust, with byte equality
for all five Rust files. The 100 inputs are compiled and executed in each language
under six runtime configurations (memo off/on × three diagnostic modes). Java's
reflection observer and Rust's canonical JSON are independently compared with the
same handwritten values. Enum occurrences retain declaring type, constant and
span; nested nodes retain mapping identity, fields and span. Typed integer inputs
also check that comparisons do not confuse numbers with text.

Container comparison deliberately tests type identity rather than element types.
Empty-container error positions use the owning rule span, since no value capture
exists. See [the contract](../../docs/typeof-constraints.md) for details.

The automatic integer evaluator case also composes numeric mapping and `@typeof`
with the generated `literal` strategy and checked conversion hooks.
