# 第三章　木の中を歩く

> 視点：結城灯里
> （手を動かしながら読めます → `story/code/Ch03TreeWalk.java`）

「7」が出た翌朝、わたしは少し調子に乗っていたと思う。優先順位の山を越えた。三階建て。形の深さ。もう怖くない——そんな顔をしていたのだろう。槙野さんは缶コーヒー片手に、いじわるそうに笑った。

「灯里ちゃん。その『建物』、いまどこにある?」

「……頭の中、ですけど」

「機械の中には?」

詰まった。わたしが書いたのは「読む順番」だけ。建物そのものは、わたしの頭の中にしかない。

「読んだ意味は、どこかに**残しておかないと**使えない。残し方が——木」

## 木にして、歩く

槙野さんが描いたのは、校庭のけやきを上下さかさにした絵だった。てっぺんにひとつの点。そこから枝が下へ。`1 + 2 * 3` を、彼女はその木にした。

```
        (＋)          ← いちばん最後にやること
        /  \
       1   (×)        ← その下にぶら下がる
           / \
          2   3
```

「てっぺんの ＋ を計算するには、先に下の × を計算しないといけない。× には 2 と 3 がいる。**上の答えを出すには、先に下に降りる**。降りて、降りて、数字まで着いたら、抱えて戻る」

「……木の、中を、歩くんですね」

槙野さんの手が止まった。「そう。それ。**木は外から眺めるな、中を歩け**」。初めて見る、まじめな目だった。

決まりごとは、たった一本に見えた。

> ある点に立ったら、まず子どもたちに「あなたの値は?」と訊く。
> 返ってきたら、自分の記号でまとめる。数字の点だけは、自分の値をそのまま返す。

簡単じゃないか、と思った。わたしは、さっそく書いた。第二章で組んだ、あの三階建ての木を、歩く係を。

## また、九

```java
// 木の子どもたち（filteredChildren）をたどって、左から計算する……つもり
double walk(Token node) {
  Double acc = null; String op = null;
  for (Token child : node.filteredChildren) {
    String t = child.getToken().orElse("").strip();
    if (t.matches("[0-9]+")) {
      double n = Double.parseDouble(t);
      acc = (acc == null) ? n : apply(acc, op, n);   // +,-,*,/ を順に
    } else { op = t; }
  }
  return acc;
}
```

`1 + 2 * 3` を歩かせる。実行。

```
1+2*3 = 9.0
```

九。

また、九だった。

第二章で、あんなに苦しんで七にしたのに。三階建てに組み直したはずなのに。木を歩いたら、また、左から順の九に、逆戻りしていた。

わたしは、しばらく、その「9.0」を見つめていた。胸の奥が、すっと冷たくなる。あの教室の、机の下のわたしが、「ほらね」と言っている気がした。やっぱり、わたしには無理なんじゃないか。

野中くんが、わたしの顔をのぞきこんで、すぐに何かを察した。「ちょっと、その木、中身、見せて」

## 踏み抜く床

野中くんが、木の子どもたちを、そのまま並べて表示させた。

```
=== filteredChildren（公開ASTビュー）===
  DigitParser  「1」
  PlusParser   「+」
  DigitParser  「2」
  MultipleParser「*」
  DigitParser  「3」
```

平らだった。

てっぺんの ＋、その下の ×——わたしが頭の中で組んだ、あの美しい三階建ては、機械の「公開ビュー」では、ぺしゃんこに潰れて、ただの一列になっていた。`1 + 2 * 3`。だから、歩いても、左から順。だから、また九。

「なんで……三階建てに組んだのに」と、わたしの声は震えていた。

そこへ、コーヒーを注ぎ足しに来た槙野さんが、画面をちらっと見て——笑った。けらけらと、ほんとうに楽しそうに。

「あー、それ。みんな踏み抜くやつ」

「みんな?」

「**パーサー書く人間、ほぼ全員、その床、踏み抜くよ**」と槙野さんは言った。「『組んだのに、平ら』。私も踏み抜いた。前任のあいつも踏み抜いた。たぶん、Unlaxer 作った本人も、昔どっかで踏み抜いてる。考えが足りないんじゃない。**みんな、同じところで、足りない**。そういう床なの」

わたしだけじゃ、なかった。

たったそれだけのことで、机の下のわたしが、ちょっとだけ、引っこんだ。

## 四人の言い争い

なぜ平らになるのか。どう直すのか。気づけば、机のまわりに、四人が集まっていた。わたし、野中くん、槙野さん——そして、画面の向こうから、玲。勉強会で連絡先を交換してから、こういうとき、なぜか彼女はすぐ現れる。

「公開ビュー（filteredChildren）はね」と槙野さんが説明した。「Chain とか Choice みたいな**構造の部品は、AST には残さない**設計なの。葉っぱ（実際にマッチした字）だけ見せる。構造は、内側に畳まれてる」

「なら」と野中くんが食いついた。勢いの人だ。「深さを手で数えればよくない? `(` で深さ＋1、みたいに。カウンタ持って——」

「それ、第二章のわたしと同じ沼です」とわたしは止めた。「`if` と手作業で枝を数えるやつ。式が複雑になると破綻する」

「じゃあ」と槙野さん。「**ルールに名前を付ける**手はある。Expression、Term、Factor を、ちゃんと名前付きの部品にすれば、AST に残せる。残せるけど——部品ぜんぶに名前と取り出し方を書くの、けっこうな手間だよ」

そこで、ずっと黙っていた玲が、口を開いた。生成派の子だ。

「——だから、**機械に作らせるの**」

画面の中で、玲は少し挑むように言った。「手で部品を組んで、構造が消えて、名前を付け直して……それ、ぜんぶ手作業でしょう。わたしの ANTLR は、文法を一枚書いたら、**構造を保った木を、道具が生成する**。あなたたちの言う『平ら問題』、最初から、起きない」

「……っ」と野中くんが言葉に詰まった。

正直、わたしも、ぐうの音も出なかった。玲の言う通りだ。わたしは、手で組んで、自分で構造を潰して、それを手で直そうとしている。マッチポンプみたいだ。

でも——槙野さんは、引かなかった。

「玲ちゃんの言うこと、半分は正しい。生成は楽だ」と槙野さんは言った。「でもね。灯里ちゃんが手で組んで、自分で潰して、いま『なんで平らになるんだ』って分かったこと。**それは、生成だけ知ってる人には、一生分からない**かもしれないよ。中で何が畳まれてるか、見たことがあるかどうか。——灯里ちゃん。あんたはもう、底を踏み抜いて、見た」

四人の間に、少しだけ、沈黙が流れた。予定調和の、きれいな結論は、出なかった。玲は「……ふん」とだけ言って、でも接続は切らなかった。野中くんは「俺、もう一回コーヒー」と言って立った。

議論は、勝ち負けじゃ終わらなかった。ただ、進む方向だけが、決まった。

## 機械に、構造ごと作らせる

槙野さんが、最後に、こう言った。

「灯里ちゃん。手で組むのは、もう十分やった。次は——**文法を一枚の紙に書いて、木も、歩く係も、機械に生成させる**。Unlaxer にも、それがある。玲ちゃんの言う『生成』を、合成派のやり方で」

それが、わたしが UBNF という紙に出会う、きっかけだった。生成された木は、平らじゃない。`1 + 2 * 3` は、ちゃんと——

```
BinaryExpr(＋)
 ├ left : 1
 └ right: BinaryExpr(×)
           ├ left : 2
           └ right: 3
```

——こういう、構造を保った木になる。そして、その木を歩く係も、機械が一緒に書き出してくれる。歩けば、ちゃんと、七になる。

> **手を動かす人へ（予告）。** この「生成された、平らじゃない木」を一枚の紙から作るのが、次章。
> 手で潰した経験があるあなたほど、生成された木のありがたみが、骨身にしみるはずです。

## 帰り道

その日、わたしは「9」を二回出した。普通なら、落ちこむ日だ。でも、なぜか、軽かった。

「みんな踏み抜く」。槙野さんのその一言が、ずっと、胸にあった。わたしの「できない」は、わたし固有の欠陥じゃなくて、この道を通る全員が、同じ床で、同じように足を取られる——その、一枚の床だった。

給湯室で、槙野さんがぽつりと言った。「前任のあいつもね。最初、その床で、半日固まってた」

「槙野さんの、大事な人だったんですね」

しばらく黙って、「うん」とだけ。窓の外は、もう暗かった。

「あいつが最後に降りていった木は」と槙野さんは言った。「平らになんて、できないくらい——深かった」

その木がどれだけ深く、底で何が待っているのか。わたしが本当にその枝を降りるのは、まだ、ずっと先のことだ。
