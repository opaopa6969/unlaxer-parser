# 第七章　二つの剣・其の一

> 視点：結城灯里
> （手を動かしながら読めます → `story/code/calc-var.ubnf` / `story/code/TinyCalcVarRun.java`）

文法が、ひととおり育ったころ。槙野さんが、あらたまった声で言った。

「灯里ちゃん。式が読めて、木にもなった。でも、それ、まだ**動いてない**よ」

「動いてます。`1+2*3` で 7 が出ます」

「それは、固定の式。じゃあ `$price * 1.1` は? `$price` の中身、いくつ?」

詰まった。`$price` は箱だ。中身は、お客さんが、あとから入れてくる。同じ式に、毎日、何百万回も、ちがう値が流れこむ。

「それを、ちゃんと動かすやり方が——剣でいうと、二振りある」槙野さんは指を二本立てた。「一本目。**木を、その場で歩く剣**」

## 文脈を、連れて歩く

値が来るたびに、木のてっぺんに立って、枝を降り、`$price` の箱に着いたら中身を見て、掛けて、戻る。来るたび、毎回。

中身を、どこから持ってくるか。わたしは、値の入った「文脈（context）」を、木を歩くときに連れて歩くことにした。`$price` に着いたら、文脈に「price の中身は?」と訊く。

第五章で UBNF に `VariableRef` を一行足してあるから、`$price` は、もうちゃんとパースできる。あとは、歩く係に、文脈を渡すだけ。

```java
static Map<String,Double> context;   // 変数の「いまの値」

static double leaf(String t) {
  t = t.strip();
  if (t.startsWith("$")) {            // 変数なら、文脈に訊く
    Double v = context.get(t.substring(1));
    if (v == null) throw new RuntimeException("変数が未定義: " + t);
    return v;
  }
  return Double.parseDouble(t);       // 数字なら、そのまま
}
```

`$price * 2`、文脈に price=100。歩かせる。

```
$price*2 = 200.0
```

同じ木に、別の値を流す。price=250, tax=10。

```
$price+$price*$tax/100 = 275.0
```

同じ一本の木が、ちがう値で、何度でも、ちがう答えを出す。わたしは、それがうれしくて、しばらく、いろんな値を流して遊んでいた。

> **手を動かす人へ。** この「一本の木に、何通りもの値を流す」は、`story/code/TinyCalcVarRun.java` で動きます（文法は `calc-var.ubnf`、`$price`/`$tax` を文脈に入れて実行）。`context` の数字を書き換えて、同じ式の答えが変わるのを味わってください。

## 未定義という、落とし穴

遊んでいて、わたしは、わざと、文脈に入れていない変数を流してみた。`$unknown + 1`。

```
$unknown+1 → 変数が未定義: $unknown
```

例外で、止まった。当たり前といえば当たり前。でも、野中くんが横で、しみじみ言った。

「これ、本番でいちばん多い事故な気がする。式は正しい。文法も通る。でも、**その日その値が、たまたま入ってなかった**」

「『たまたま入ってない』を、エラーにするか、ゼロ扱いにするか、で、また宗教戦争が起きるやつ」と、コーヒーを注ぎに来た槙野さんが笑った。「うちは『止める』派。黙ってゼロにすると、不正検知が、こっそり甘くなるから。——灯里ちゃん、`null` を黙って通すコード、いちばん憎みなさい」

`null` を、黙って通さない。わたしは、それを、ルール帳に書いた。これは、文法の話じゃない。式エンジンが、人の仕事に、責任を持つ、という話だった。

## 型という、約束

もうひとつ、厄介なやつがいた。**型**。

`3 + 4` は 7。数の足し算。じゃあ `"abc" + "def"` は? `"abcdef"`。文字の、くっつけ。同じ `＋` なのに、数なら足して、文字ならくっつける。

野中くんが、目を輝かせた。「じゃあさ、`"3" + 4` は? 7? それとも `"34"`?」

わたしは、答えに詰まった。木を歩いて `＋` に着いたとき、左と右が「数」なのか「文字」なのかを、知らないと、足せない。

「そこ」と槙野さんが、急に真顔になった。「そこが、二本目の剣と、それから——あの五十三分の式に、ぜんぶ、つながっていく。**型は、その値が『どう振る舞うか』の約束**。数は足される。文字はくっつく。真偽は、本当か嘘か。木のそれぞれの点に、『あなたは何型?』の札を、ちゃんと下げてやらないと、`＋` は、自分が何をすればいいか、分からない」

わたしたちの作っている本物の式エンジンは、ここを、`P4TypedAstEvaluator` という、型の札をちゃんと見て歩く評価器でやっている。`"3"+4` みたいな混ざりものを、宣言された型を頼りに、正しく裁く。この練習用の `TinyCalcVarRun` は、数だけの世界だから、まだ、その重さを背負っていない。——でも、いつか背負う。

> **手を動かす人へ（発展）。** `TinyCalcVarRun` に「文字列の変数」と「文字どうしの ＋ はくっつける」を足してみてください。`"3"+4` を、あなたなら、どう裁きますか。その選択に、あなたの言語の「人格」が出ます。

## 蕎麦屋で

その週末、わたしは祖母を、近所の蕎麦屋に連れていった。初任給の、二度目だ。

祖母は品書きを眺めて、「お前、これ、ぜんぶ計算できるのか」と冗談を言った。わたしは、なぜか真剣に答えていた。

「天ぷらが、いくらで。それが、何枚で。割引が、あるかないかで。——そういうのを、一個ずつ、**型の約束を確かめながら**、足したり掛けたりするのが、わたしの仕事だよ。あと、値が入ってなかったら、ちゃんと止まる」

祖母は、よく分からない、という顔で、でも、うれしそうに笑った。「むかし、お前は、伝票の足し算もよう間違えとったのにな」

ほんとうだ。伝票を間違えていた子が、いまは、機械に、足し算のやり方そのものを、約束ごと教えている。型の札を、一枚ずつ。

## 一本目の、弱点

一本目の剣は、こうして手に馴染んだ。けれど槙野さんは言った。

「この剣には、弱点がある。**毎回、いちから歩く**。何百万回でも、律儀に、いちから。式が、ばかみたいに大きいと——歩くだけで、日が暮れる」

日が暮れる。そのとき、わたしは軽く聞き流していた。五十三分という日暮れが、もうすぐそこまで来ているのを、知らずに。

「だから、二本目を打つ」と槙野さんは言った。「木を、毎回歩くんじゃなくて——いちど、Java の文章に**翻訳して**、コンパイルして、機械にじかに走らせる剣を」

それが、彼が——前任者が——いちばん愛して、いちばん深く迷い込んだ、二本目の剣の話だった。
